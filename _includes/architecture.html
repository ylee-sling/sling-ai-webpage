How it works

A two-stage architecture: the Brain sets the milestone, the Muscle moves

Stage 1

The Brain — Visual Milestone Planner

A shared vision encoder reads the camera frames and goal image, and a frozen CLIP text encoder reads the instruction. A neuro-symbolic skill selector then applies discrete, rule-like logic to decide which skill comes next, for example “reach above handle” → “grasp handle”.

A JEPA predictor forecasts what the scene should look like when that milestone is reached. A milestone only advances once the robot's latent state crosses a threshold, which keeps small errors from piling up across task phases.

Stage 2

The Muscle — Flow-Matching Motion Engine

Given the predicted milestone, a flow-matching solver integrates a learned velocity field for a fixed number of steps (K) and outputs the entire continuous arm-and-gripper trajectory chunk at once, not one coordinate at a time.

Because the motion is solved as a smooth curve, the arm moves fluidly toward the milestone while the Brain is already planning the next one.

Key takeaway: latency no longer depends on token count or sentence structure. Every decision costs the same fixed amount of compute, so the robot receives a fresh, smooth trajectory every 10–14 ms instead of waiting for a language model to finish “speaking.”
